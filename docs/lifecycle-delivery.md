# 资源生命周期改造

分支：`feat/resource-lifecycle`，基于 main `fa91ad8`。

## 第一阶段（P0）

- 已保存 HTTP / MCP / 命令行用例有独立入口，支持查找、类型筛选、详情、编辑、复制、勾选运行、归档和恢复。
- 流程接通归档、恢复、已归档列表和搜索；归档定义只读，新运行会在服务层拒绝。
- 服务和数据库定义退出使用前检查有效流程引用（包含禁用步骤）；MCP 检查有效用例引用。
- 定义变更与执行快照使用同一生命周期锁；SQL、MCP 和服务启动期间有使用保留；运行快照保护尚未执行的依赖。
- 已取得快照的执行继续完成；归档不取消运行。
- 归档接口或分组不能直接执行保存的定义；独立用例的请求副本保持独立。
- 正在执行、已固定、被用例批次或流程详情引用的 HTTP 底层记录不能单独删除。
- 读取历史服务日志不再要求服务定义仍存在。

验证：JavaScript 语法检查、32 项前端测试和 Go 全量测试、Runtime 构建及 HTTP / 服务 / 数据库 / MCP 客户端竞态检测通过。新增回归覆盖归档中完成执行、不可变快照、禁用步骤引用、未来步骤占用、缺失依赖恢复以及移除配置后读取日志。

## 后续交付

第二阶段：连接类配置的可恢复归档、接口与分组恢复、引用影响入口、查询与记录管理、AI 接入移除。

第三阶段：逐项报告的批量操作、归档配置彻底删除、默认关闭且可预览的自动保留策略。文档明确为将来独立立项的项目与环境管理不在本轮扩展。

## 接口兼容安排

- `DELETE /test-cases/:id` 和 `DELETE /flows/:id` 继续表示软归档；`GET` 可读取已归档定义，默认列表仅返回有效定义。
- `DELETE /mcp-servers/:id` 继续表示软归档，新增运行占用和有效用例引用保护。
- 第一阶段的服务、数据库 `DELETE` 保留原有硬删除语义，并先执行引用及运行保护；第二阶段提供明确的归档端点和页面入口，旧端点保留兼容安排。
- `DELETE /runs/:id` 增加保护条件，拒绝破坏完整批次/流程详情；整组清理由后续独立端点负责。
- 不清理草稿，不重写已有 ID、凭据或历史，不自动找回已硬删除的配置。
