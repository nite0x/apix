# 资源生命周期改造

分支：`feat/resource-lifecycle`，基于 main `fa91ad8`。

## 第一阶段（P0）

- 已保存 HTTP / MCP / 命令行用例有独立入口，支持查找、类型筛选、详情、编辑、复制、勾选运行、归档和恢复。
- 流程接通归档、恢复、已归档列表和搜索；归档定义只读，新运行会在服务层拒绝。
- 服务和数据库定义退出使用前检查有效流程引用（包含禁用步骤）；MCP 检查有效用例引用。
- 定义变更与执行快照使用同一生命周期锁；SQL、MCP 和服务启动期间有使用保留；运行快照保护尚未执行的依赖。
- 已取得快照的执行继续完成；归档不取消运行。
- 归档接口或分组不能直接执行保存的定义；独立用例的请求副本保持独立。
- 正在执行、已固定、被用例批次或流程详情引用的 HTTP 底层记录不能单独删除。
- 读取历史服务日志不再要求服务定义仍存在。

验证：JavaScript 语法检查、32 项前端测试和 Go 全量测试、Runtime 构建及 HTTP / 服务 / 数据库 / MCP 客户端竞态检测通过。新增回归覆盖归档中完成执行、不可变快照、禁用步骤引用、未来步骤占用、缺失依赖恢复以及移除配置后读取日志。

## 交付范围

第二阶段（已完成）：连接类配置的可恢复归档、接口与分组恢复、引用影响入口、查询与记录管理、AI 接入移除。

第三阶段（已完成）：逐项报告的批量操作、归档配置彻底删除、默认关闭且可预览的自动保留策略。文档明确为将来独立立项的项目与环境管理不在本轮扩展。

## 接口兼容安排

- `DELETE /test-cases/:id` 和 `DELETE /flows/:id` 继续表示软归档；`GET` 可读取已归档定义，默认列表仅返回有效定义。
- `DELETE /mcp-servers/:id` 继续表示软归档，新增运行占用和有效用例引用保护。
- 第一阶段的服务、数据库 `DELETE` 保留原有硬删除语义，并先执行引用及运行保护；第二阶段提供明确的归档端点和页面入口，旧端点保留兼容安排。
- `DELETE /runs/:id` 增加保护条件，拒绝破坏完整批次/流程详情；整组清理由后续独立端点负责。
- 不清理草稿，不重写已有 ID、凭据或历史，不自动找回已硬删除的配置。

## 第二阶段（P1）

- 服务和数据库新增显式 `POST .../:id/archive` 与 `POST .../:id/restore`；归档保留原 ID、配置及加密凭据，默认列表和执行选择器隐藏归档项。数据库另有归档后清除凭据入口。
- MCP 提供已归档列表、详情、恢复和发现时间；恢复先握手并重新发现工具，结构发生变化时相关用例需要检查、重新保存。
- 接口和分组可以从归档列表恢复；恢复分组不会复活单独归档的接口，接口可以改名或选择有效分组恢复。增加接口复制、移动分组和引用影响入口。
- 服务、数据库、MCP、流程及独立用例都有搜索入口；流程展示依赖状态，SQL 历史明确显示原连接已归档或删除。
- `GET /execution-records` 查询全部批次，支持名称/目标、来源类型、状态、时间、隐藏状态及分页。原 `GET /test-batches` 继续返回最近 100 条有效列表。
- 批次固定、可恢复隐藏、整组清理使用独立接口；清理先生成 10 分钟有效的预览，确认时重新核对状态与所有关联详情。固定的批次/HTTP 记录与运行中数据均受保护。
- 服务日志支持跨已归档/已删除来源查询、时间/级别/文本筛选及分页；明确显示每服务 2,000 条、单条 8 KB 上限。“清空屏幕显示”与存储清理分开，清理预览不会删除预览后新增的日志。
- AI 接入提供按目标系统预览与移除，只处理识别出的 Apix 项，修改前备份并复查文件指纹；用户添加字段或修改配置时停止自动移除并展示差异字段。TRAE 提供手动步骤，不把用户操作视为验证成功。
- 服务、数据库旧 `DELETE` 暂保留硬删除语义，返回 `Deprecation: true`，并继续执行引用与运行保护；页面改用显式归档端点。

验证：JavaScript 语法检查、35 项前端测试、Go 全量测试和 Runtime 构建通过。新增回归覆盖凭据保留/清除、分组恢复、同名冲突、MCP 恢复校验、100 条以外查询、固定与清理竞争、日志预览边界和 AI 配置文件竞争。使用隔离数据库的 Chromium 实测用例运行、用例/服务/数据库归档恢复、记录固定和日志查询入口；无前端异常，390px 视口无横向溢出。


## 第三阶段（P2）

- 统一资源批量管理入口覆盖服务、数据库、MCP、接口、分组、独立用例和流程；每批最多 100 项，逐项返回成功、失败原因及副本 ID。支持相应资源的归档、恢复和复制。
- 服务、数据库与 MCP 连接副本使用新 ID，不复制运行状态或历史；数据库和 MCP 默认不复制凭据，数据库副本必须显式补填密码（允许用户明确选择空密码）后才能使用。
- 彻底删除必须先归档，再预览、确认；单次预览有效期 10 分钟，执行时重新核对配置指纹、引用和占用。包括已归档定义、禁用步骤在内的全部定义引用都需要先处理。
- 接口来源可以明确选择“保留副本并解除来源关联”；保留用例、流程步骤和草稿内容及来源身份记录，更新编辑版本，随后才允许彻底删除来源配置。不自动清理草稿。
- 删除用例或流程定义时解除历史外键，保留运行快照、版本、断言、HTTP 详情和必要名称。原流程历史深链在定义删除后仍可独立打开。
- 服务与数据库页面携带 `edit_version`，并发修改冲突保留输入；归档/恢复也推进版本。兼容旧客户端缺省版本字段的调用，新客户端应携带读取到的版本号。
- 记录支持按 HTTP、SQL、MCP、命令行、服务类型查询；查询、清理工作台日志同时覆盖服务输出和 Runtime 事件。日志按来源、时间、文本、级别查询；清理不影响测试结果或操作结果，预览后新增内容保留。Runtime 本地日志文件独立留存，此入口不修改该文件。
- 自动保留策略默认关闭，支持 1–3650 天、影响预览和运行报告。启用后按完整批次/运行的结束时间检查，每小时及 Runtime 重启时执行；隐藏不等于固定，固定整组或含固定 HTTP 详情的整组都会跳过。仍有进程清理失败占用的记录也受保护。
- 自动清理每组都重新核对保护条件，停用或修改策略会阻止后续待执行清理；保存策略本身不立即删除数据。`expires_at` 不作为自动删除授权。
- REST 与 MCP 使用同一服务层；新增资源生命周期、删除预览、记录查询/管理/清理和保留策略的 MCP 工具。
- HTTP schema 升级到 v8，原 v7 及既有可升级版本采用增量迁移。保留 ID、凭据和历史；旧 Runtime 会拒绝未知的新版本，避免忽略新增生命周期状态。

最终验证：JavaScript 语法检查、38 项前端测试、Go 全量测试及全量竞态检测通过；Linux Runtime 构建及 Windows amd64 交叉编译通过。新增覆盖批量部分失败、无凭据副本、完整引用保护、过期/变化预览、删除后独立历史和草稿、精确 SQL 记录清理、固定整组保护、默认关闭/停用保留策略、v7 升级及并发版本冲突。

真实 Chromium 使用隔离数据库验证了批量归档与彻底删除、删除后的历史深链、并发冲突保留草稿、保留策略预览和开关；重启升级后 schema v8、历史和策略保持一致，外键检查为 0 项异常。桌面及 390px 视口没有前端异常或横向溢出。

## 最终接口兼容约定

| 接口 | 最终语义 |
| --- | --- |
| 服务、数据库旧 `DELETE` | 仍是硬删除配置，返回弃用提示；新增“必须已归档”的前置条件，并阻止所有未处理定义引用和运行占用。未归档返回 409，不会隐式改为归档。 |
| MCP、接口、分组、用例、流程原 `DELETE` | 继续软归档，历史保留。 |
| `POST /services/:id/archive`、`POST /database/connections/:id/archive` | 明确的可恢复归档；页面日常退出使用采用这些入口。 |
| 各模块 `POST .../:id/restore` | 恢复原 ID；检查依赖、分组及名称冲突，可改名后重试。 |
| `POST /lifecycle/:kind/:id/purge-preview`、`POST /lifecycle/actions` | 新的统一彻底删除/批量入口；删除操作需要匹配的预览令牌。 |
| `DELETE /runs/:id` | 保留单条删除语义，保护运行中、固定、被批次或流程引用的底层详情。 |
| `GET /execution-records` 与清理预览/确认接口 | 查询完整范围并分页；按完整组清理，隐藏与固定独立管理。 |
| `GET/PUT /retention-policy`、`POST /retention-policy/preview` | 显式选择自动清理，默认关闭，可先预览。 |

本轮不扩展业务流程编排、人工处理或暂停规则；文档中明确留待独立立项的项目与环境管理仍属于后续工作。未推送、发布或部署，不改动用户现有运行数据。
